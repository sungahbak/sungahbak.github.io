timeout = 패킷이 어딘가에서 조용히 버려졌다.

SG(보안그룹) : stateful (상태기억, 허용만 - 한 번 통과하면 그 상태를 기억해서 다시 허용할 필요가 없다.)
NACL(서브넷) : stateless (상태기억못함, 허용+거부 - 규칙 거부 낮은 순서대로 )

NACL은 왕복을 기억하지 못하니까, 응답 패킷용 규칙을 따로 열어야 해서. 그런데 그 응답이 돌아오는 포트는 22번이 아니야.

바스티온:48392  →  10.0.2.53:22     (요청)
10.0.2.53:22    →  바스티온:48392   (응답)  ← 여기

클라이언트 쪽 포트는 매번 랜덤하게 바뀌는 임시 포트(ephemeral port, 보통 1024–65535) 야. 그래서 NACL을 커스텀으로 만들면 outbound에 1024–65535를 열어줘야 SSH가 돼. 22번만 열어두면 요청은 나가는데 응답이 NACL에서 버려져.

 ssh -p 2222 ec2-user@IP    │ 2222 허용 │ Connection refused    
 ssh -p 2222 ec2-user@IP    │ 2222 삭제 │ Connection timed out     

차이가 이 실험의 전부야. 같은 포트 2222, 같은 명령어. SG에 규칙이 있으면 패킷이 인스턴스까지 가서 "그 포트 안 듣는다"고 RST로 거절당해 → refused. SG 규칙을 지우면 패킷이 SG에서 조용히 버려져 → timeout.

그리고 그때 증상이 뭐냐 — Connection timed out. SG가 막은 것과 완전히 똑같다.
